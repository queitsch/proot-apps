#+TITLE: PRoot Apps

A [[https://github.com/linuxserver/proot-apps][PRoot Apps]] repository built the same way as linuxserver/proot-apps, so it
can be added to a [[https://github.com/selkies-project/sealskin][SealSkin]] PRoot Apps catalog by its GitHub ~owner/repo~.

* Apps

| Name  | Full endpoint                         | Category    | Arch                    |
|-------+---------------------------------------+-------------+-------------------------|

** emacs

GNU Emacs from Alpine 3.24 (~emacs-pgtk~ and ~emacs-gtk3~, Emacs 30.2). The
image holds two builds of the same release:

| Binary                         | Build          | Used when                                |
|--------------------------------+----------------+------------------------------------------|
| ~/usr/bin/emacs~               | pure GTK, pgtk | the session has a Wayland display        |
| ~/usr/libexec/emacs-x11/emacs~ | GTK3 on X11    | there is no Wayland socket but ~DISPLAY~ is set |

The entrypoint prefers Wayland: it starts the pgtk build when
~$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY~ (or an absolute ~WAYLAND_DISPLAY~) is a
socket, and the X11 build otherwise. Set ~PA_EMACS_BACKEND=pgtk~ or
~PA_EMACS_BACKEND=x11~ to force one.

Alpine's ~emacs-pgtk~ and ~emacs-gtk3~ packages conflict, so the X11 binary and
its dump file come from a second build stage. Both packages ship
byte-identical Lisp. Only the binary and its fingerprint-named ~.pdmp~ differ,
so the two dump files sit side by side in ~/usr/lib/emacs/30.2/<triplet>/~.

On install the app adds an ~Emacs PA~ start menu entry and desktop shortcut.
It also adds ~emacs-pa~ to ~$HOME/.local/bin~ for the command line.

* Adding this repository to SealSkin

In the SealSkin admin UI open the PRoot Apps catalogs, click *New Catalog* and
set the remote to:

#+begin_example
queitsch/proot-apps
#+end_example

SealSkin reads a GitHub ~owner/repo~ remote as
~https://raw.githubusercontent.com/<owner>/<repo>/master/metadata/metadata.yml~,
with the icons under ~metadata/img/~. It installs the apps as the images
~ghcr.io/<owner>/<repo>:<name>~ and uses the first layer of each. See
~Remote.parse~ in [[https://github.com/selkies-project/sealskin/blob/main/server/app/prootapps.py][server/app/prootapps.py]] and the "PRoot Apps remotes" section
of SealSkin's ~docs/content/registries.md~. Because of that:

- the metadata has to be on the ~master~ branch, and
- the images have to be pullable from ghcr.io (see below).

A remote can also be given as a base URL and a registry, one space apart. That
form serves the metadata from any branch:

#+begin_example
https://raw.githubusercontent.com/queitsch/proot-apps/<branch> ghcr.io/queitsch/proot-apps
#+end_example

* Building and publishing

~.github/workflows/build-on-commit.yml~ builds every app whose ~apps/<name>/~
folder changed on a push to ~master~. It pushes the app to
~ghcr.io/<owner>/<repo>:<name>~ for the architectures in
~metadata/metadata.yml~. Run the workflow by hand with /Build and push all apps/
to build everything.

The apps build on the public base images of linuxserver/proot-apps
(~ghcr.io/linuxserver/proot-apps:alpine-324~), so this repository builds no
base images of its own.

GitHub publishes a new container package as private, and the package does not
take on the repository's visibility. See [[https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry][Working with the Container registry]]
and [[https://docs.github.com/en/packages/learn-github-packages/configuring-a-packages-access-control-and-visibility][Configuring a package's access control and visibility]]. After the first
build, open the ~proot-apps~ package, go to *Package settings*, then *Danger
Zone*, then *Change visibility*, and pick *Public*. Public images can be pulled
anonymously. The other choice is to give the SealSkin nodes a credential for
ghcr.io.

* Using the apps without SealSkin

With [[https://github.com/linuxserver/proot-apps#install-or-update][proot-apps]] installed:

#+begin_src sh
proot-apps install ghcr.io/queitsch/proot-apps:emacs
#+end_src

* Building an app locally

#+begin_src sh
cd apps/emacs
docker build --build-arg REPO=queitsch/proot-apps -t local-emacs .
#+end_src

The image is a single layer. Extract it into
~$HOME/proot-apps/ghcr.io_queitsch_proot-apps_emacs/~ the way
linuxserver/proot-apps' ~build-install-local~ does, then run it:

#+begin_src sh
proot-apps run ghcr.io/queitsch/proot-apps:emacs
#+end_src

* Adding an app

Follow "Adding a new app" in the [[https://github.com/linuxserver/proot-apps#adding-a-new-app][linuxserver/proot-apps README]]:

1. Create ~apps/<name>/~ with ~Dockerfile~, ~entrypoint~, ~install~ and ~remove~.
2. Add an entry to ~metadata/metadata.yml~ with ~name~, ~full_name~, ~arch~,
   ~category~, ~icon~ and ~description~.
3. Put the icon in ~metadata/img/~.
